## 1. 题目描述

- [leetcode](https://leetcode.cn/problems/game-of-life/)

根据 [百度百科](https://baike.baidu.com/item/%E7%94%9F%E5%91%BD%E6%B8%B8%E6%88%8F/2926434?fr=aladdin)，游戏，简生命，国数约翰·何顿·康威在 1970 年发明的细胞自动机。

给定一个包含 `m × n` 个格子的面板，每一个格子都可以看成是一个细胞。每个细胞都具有一个初始状态：`1` 即为活细胞（live），或 `0` 即为死细胞（dead）。每个细胞与其八个相邻位置（水平，垂直，对角线）的细胞都遵循以下四条生存定律：

1. 如果活细胞周围八个位置的活细胞数少于两个，则该位置活细胞死亡；
2. 如果活细胞周围八个位置有两个或三个活细胞，则该位置活细胞仍然存活；
3. 如果活细胞周围八个位置有超过三个活细胞，则该位置活细胞死亡；
4. 如果死细胞周围正好有三个活细胞，则该位置死细胞复活；

下一个状态是通过将上述规则同时应用于当前状态下的每个细胞所形成的，其中细胞的出生和死亡是同时发生的。给你 `m x n` 网格面板 `board` 的当前状态，返回下一个状态。

给定当前 `board` 的状态，`board` 到下一个状态。

注意：你不需要返回任何东西。

## 2. s.1 - 原地标记

::: code-group

```c [c]
void gameOfLife(int** board, int boardSize, int* boardColSize) {
    int m = boardSize, n = boardColSize[0];
    int dirs[] = {-1, 0, 1};
    for (int i = 0; i < m; i++) {
        for (int j = 0; j < n; j++) {
            int live = 0;
            for (int di = 0; di < 3; di++) {
                for (int dj = 0; dj < 3; dj++) {
                    if (dirs[di] == 0 && dirs[dj] == 0) continue;
                    int ni = i + dirs[di], nj = j + dirs[dj];
                    if (ni >= 0 && ni < m && nj >= 0 && nj < n && (board[ni][nj] & 1)) live++;
                }
            }
            if (board[i][j] & 1) {
                if (live == 2 || live == 3) board[i][j] |= 2;
            } else {
                if (live == 3) board[i][j] |= 2;
            }
        }
    }
    for (int i = 0; i < m; i++)
        for (int j = 0; j < n; j++)
            board[i][j] >>= 1;
}
```

```js [js]
/**
 * @param {number[][]} board
 * @return {void} Do not return anything, modify board in-place instead.
 */
var gameOfLife = function (board) {
  const m = board.length,
    n = board[0].length
  const dirs = [-1, 0, 1]
  for (let i = 0; i < m; i++) {
    for (let j = 0; j < n; j++) {
      let live = 0
      // 统计 board[i][j] 周围的活细胞数量
      for (const di of dirs) {
        for (const dj of dirs) {
          if (di === 0 && dj === 0) continue // 跳过自身
          const ni = i + di,
            nj = j + dj
          if (ni >= 0 && ni < m && nj >= 0 && nj < n && board[ni][nj] & 1)
            live++
        }
      }
      // 第二位记录下一状态
      if (board[i][j] & 1) {
        // 定律 2
        if (live === 2 || live === 3) board[i][j] |= 2
      } else {
        // 定律 4
        if (live === 3) board[i][j] |= 2
      }
      // 定律 1、3 的死亡情况无需处理，因为 board[i][j] 第二位默认就是 0
    }
  }
  for (let i = 0; i < m; i++) {
    for (let j = 0; j < n; j++) {
      board[i][j] >>= 1
    }
  }
}
```

```py [py]
class Solution:
    def gameOfLife(self, board: List[List[int]]) -> None:
        """
        Do not return anything, modify board in-place instead.
        """
        m, n = len(board), len(board[0])
        for i in range(m):
            for j in range(n):
                live = 0
                for di in (-1, 0, 1):
                    for dj in (-1, 0, 1):
                        if di == 0 and dj == 0:
                            continue
                        ni, nj = i + di, j + dj
                        if 0 <= ni < m and 0 <= nj < n and (board[ni][nj] & 1):
                            live += 1
                if board[i][j] & 1:
                    if live in (2, 3):
                        board[i][j] |= 2
                else:
                    if live == 3:
                        board[i][j] |= 2
        for i in range(m):
            for j in range(n):
                board[i][j] >>= 1
```

:::

- 时间复杂度：$O(m \times n)$，其中 $m$ 和 $n$ 是矩阵的行数和列数
- 空间复杂度：$O(1)$，原地修改

算法思路：

- 用第二位记录下一状态：低位是当前状态，高位是下一状态
- 统计每个细胞周围活细胞数（用 `& 1` 取当前状态），根据规则设置高位
- 最后统一右移一位得到最终状态

## 3. 【AI】回复「进阶」描述中提到的问题：“当活细胞侵占了面板边界时会造成问题”

原文：“本题中，我们使用二维数组来表示面板。原则上，面板是无限的，但当活细胞侵占了面板边界时会造成问题。你将如何解决这些问题？”

### 3.1. 理解问题

这句话是在说：生命游戏**理论上是在一个无限大的二维网格上进行的**，但我们在代码里只能用**有限的二维数组**来表示面板。这就产生了一个矛盾：如果活细胞跑到了数组边界之外，我们没法表示它们。

具体来说，假设你有一个 `m × n` 的数组。对于边界上的细胞，比如 `(0, 0)`，它的八个邻居里有三个在数组外面：`(-1, -1)`、`(-1, 0)`、`(0, -1)`。按照生命游戏的规则，这些数组外的格子应该被当作**死细胞**来处理。如果我们在统计邻居时直接忽略它们，那其实就相当于默认它们是死的，这在当前这一步是没问题的。

但问题在于：**如果某个活细胞通过繁殖，下一个状态应该出现在数组之外，你该怎么办？**  

比如 `(0, 0)` 是死细胞，周围正好有三个活细胞，那么下一步 `(0, 0)` 会变成活细胞——这还能表示。但如果 `(-1, 0)` 也应该变成活细胞呢？你的数组根本没有这个位置，这个新生的活细胞就被丢掉了。反过来，如果边界外的活细胞应该影响边界内的细胞，你也无法知道，因为你没有存储它们。

所以“活细胞侵占了面板边界”指的就是：细胞的演化超出了你预先分配的有限数组范围，导致模拟结果和无限棋盘上的真实结果不一致。

### 3.2. 解决方案

**如何解决？** 常见思路有两种：

#### 只存储活细胞的坐标

不用二维数组存整个网格，而是用一个哈希表或集合（Set）只记录所有活细胞的坐标。每一步，遍历当前所有活细胞以及它们周围的邻居（这些邻居可能是死细胞，但需要检查是否会复活），计算它们下一轮的状态。这样棋盘可以无限大，因为你只关心活细胞及其影响范围，死细胞不占存储。当活细胞跑到很远的地方时，集合里自然会有新的坐标，不会丢失。

#### 动态扩展数组

如果坚持用二维数组，可以在活细胞接近边界时，扩大数组（比如上下左右各加一圈），并初始化新格子为死细胞。这样边界问题就暂时解决了，但每次扩展都要复制数据，效率较低，而且如果无限扩展，数组会越来越大。

### 小结

LeetCode 上的这道题通常只要求处理**给定大小的面板**，并默认边界外都是死细胞，所以不需要真正实现无限扩展。进阶问题只是在启发你思考：如果要在无限棋盘上模拟，该怎么设计数据结构。
