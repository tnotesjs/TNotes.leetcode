## 1. 题目描述

- [leetcode](https://leetcode.cn/problems/combination-sum-iv/)

给你一个由不同整数组成的数组 `nums`，和一个目标整数 `target`。请你从 `nums` 中找出并返回总和为 `target` 的元素组合的个数。

题目数据保证答案符合 32 位整数范围。

---

示例 1：

```txt
输入：nums = [1, 2, 3], target = 4
输出：7
```

解释：

所有可能的组合为：

- `(1, 1, 1, 1)`
- `(1, 1, 2)`
- `(1, 2, 1)`
- `(1, 3)`
- `(2, 1, 1)`
- `(2, 2)`
- `(3, 1)`

请注意，顺序不同的序列被视作不同的组合。

---

示例 2：

```txt
输入：nums = [9], target = 3
输出：0
```

---

提示：

- `1 <= nums.length <= 200`
- `1 <= nums[i] <= 1000`
- `nums` 中的所有元素互不相同
- `1 <= target <= 1000`

---

进阶：如果给定的数组中含有负数会发生什么？问题会产生何种变化？如果允许负数出现，需要向题目中添加哪些限制条件？

## 2. s.1 - 动态规划

::: code-group

```c [c]
int combinationSum4(int* nums, int numsSize, int target) {
    unsigned int* dp = (unsigned int*)calloc(target + 1, sizeof(unsigned int));
    dp[0] = 1;
    for (int i = 1; i <= target; i++) {
        for (int j = 0; j < numsSize; j++) {
            if (i >= nums[j]) dp[i] += dp[i - nums[j]];
        }
    }
    int res = (int)dp[target];
    free(dp);
    return res;
}
```

```js [js]
/**
 * @param {number[]} nums
 * @param {number} target
 * @return {number}
 */
var combinationSum4 = function (nums, target) {
  const dp = new Array(target + 1).fill(0)
  dp[0] = 1
  for (let i = 1; i <= target; i++) {
    for (const num of nums) {
      if (i >= num) dp[i] += dp[i - num]
    }
  }
  return dp[target]
}
```

```py [py]
class Solution:
    def combinationSum4(self, nums: List[int], target: int) -> int:
        dp = [0] * (target + 1)
        dp[0] = 1
        for i in range(1, target + 1):
            for num in nums:
                if i >= num:
                    dp[i] += dp[i - num]
        return dp[target]
```

:::

- 时间复杂度：$O(n \times target)$，其中 $n$ 是数组长度
- 空间复杂度：$O(target)$

算法思路：

- 完全背包变体，考虑排列而非组合
- $dp[i]$ 表示和为 $i$ 的排列数，外层枚举目标，内层枚举数字

### 2.1. 转移：`dp[i] += dp[i - num]`

- `dp[i]` 表示和为 `i` 的排列数
- `dp[i - num]` 表示和为 `i - num` 的排列数
- 外层 `i` 表示目标数
- 内层 `num` 表示凑到目标数时使用的排列的结尾数
- 要凑出 `i`，最后一步可以放任意一个 `num`（且 `num ≤ i`），前面那段必须正好凑成 `i - num`。

### 2.2. `dp[i]` 排列数计算流程

以 `dp[3]` 为例，要凑出 `3`，合法排列有：`(1,1,1)`、`(1,2)`、`(2,1)`、`(3)`。

算 `dp[3]` 时，问的是：「最后一步放哪个数？」

- 最后放 `1` → 前面要凑 `2`，贡献 `dp[2]`（里面已经含 `(1,1)` 和 `(2)`）→ 得到 `(1,1,1)`、`(2,1)`
- 最后放 `2` → 前面要凑 `1`，贡献 `dp[1]` → 得到 `(1,2)`
- 最后放 `3` → 前面要凑 `0`，贡献 `dp[0]` → 得到 `(3)`

所以 `(1,2)` 和 `(2,1)` 分别挂在「最后是 2」「最后是 1」两条路上，各算一次。

- 内层 `nums` 循环是在问要凑到目标数 `i`，序列的 **最后一位** 用哪个 `num`。
- 最后一位 `num` 不同 -> 整段序列不同 -> 排列自然分开 -> 单独计算。
- 题目提示里写了「`nums` 中的所有元素互不相同」。这对内层循环有用：扫 `nums` 时，同一个「最后一位取值」不会因为数组里出现重复元素而被加两次。
- 这不限制序列里能不能反复用同一个数：完全背包下每个 `num` 仍可多次出现，例如 `(1,1,1)` 合法。互不相同只避免「数组里有两个相同的 `num` 导致最后一位被重复统计」。

### 2.3. 「算排列：外层 `i`、内层 `num`」 vs 「算组合：外层 `num`、内层 `i`」

**本题做法：外层 `i`、内层 `num`，但如果反过来（外层 `num`、内层 `i`）则不行**。因为反过来的话是在按「先考虑用不用这个数」堆组合，通常会把「选了哪些数」当成无序集合来数，`(1,2)` 和 `(2,1)` 不会分开成两种。那是组合数背包，不是这题。

在「完全背包、求方案数」这个语境下可以这么记：

- **外层 `i`、内层 `num`** → 按「最后一位加什么」转移 → **排列**
- **外层 `num`、内层 `i`** → 按「这个数用不用」转移 → **组合**
