## 1. 题目描述

- [leetcode](https://leetcode.cn/problems/guess-number-higher-or-lower-ii/)

我们正在玩一个猜数游戏，游戏规则如下：

1. 我从 `1` 到 `n` 之间选择一个数字。
2. 你来猜我选了哪个数字。
3. 如果你猜到正确的数字，就会赢得游戏。
4. 如果你猜错了，那么我会告诉你，我选的数字比你的更大或者更小，并且你需要继续猜数。
5. 每当你猜了数字 `x` 并且猜错了的时候，你需要支付金额为 `x` 的现金。如果你花光了钱，就会输掉游戏。

给你一个特定的数字 `n`，返回能够确保你获胜的最小现金数，不管我选择那个数字。

## 2. 题目解读

这道题（LeetCode 375. 猜数字大小 II【中等】）是一道非常经典的 **博弈论 + 动态规划（区间 DP）** 问题。

与普通的二分猜数字（LeetCode 374. 猜数字大小【简单】）不同，这道题 **没有给你具体的 `pick` 目标数字**，而是让你制定一个 **必胜策略**，求这个策略在最坏情况下所需的 **最小现金数**。

- **目标**：确保在任何可能的数字下都能赢，且 **花费的现金最少**。
- **规则**：猜错才付钱（付你猜的数字 `x`）。猜对了不用付钱（或者说是最后一次猜对时不用付钱，前面的错误猜测已经付过了）。
- **本质**：这是一场你与“出题人”的博弈。出题人会故意引导你走向花费最大的路径（最坏情况）。你需要在这个最坏情况下，找出 **最少的开销**。即 **极小化极大（Minimax）** 策略。

## 3. s.1 - 区间 DP

::: code-group

```c [c]
int getMoneyAmount(int n) {
    int dp[n + 2][n + 2];
    memset(dp, 0, sizeof(dp));
    for (int len = 2; len <= n; len++) {
        for (int i = 1; i + len - 1 <= n; i++) {
            int j = i + len - 1;
            dp[i][j] = INT_MAX;
            for (int k = i; k <= j; k++) {
                int left = dp[i][k - 1], right = dp[k + 1][j];
                int cost = k + (left > right ? left : right);
                if (cost < dp[i][j]) dp[i][j] = cost;
            }
        }
    }
    return dp[1][n];
}
```

```js [js]
/**
 * @param {number} n
 * @return {number}
 */
var getMoneyAmount = function (n) {
  const dp = Array.from({ length: n + 2 }, () => new Array(n + 2).fill(0))
  
  // 枚举区间长度从小 -> 大（从 2 到 n）
  for (let len = 2; len <= n; len++) {
    // 区间起点
    for (let i = 1; i + len - 1 <= n; i++) {
      // j 代表区间终点
      const j = i + len - 1
      // dp[i][j] 表示在 [i, j] 区间中确保胜利的最小成本
      dp[i][j] = Infinity
      for (let k = i; k <= j; k++) {
        // 猜 k 确保胜利，需考虑最坏花费 = k + 左右子区间的最大花费
        const cost = k + Math.max(dp[i][k - 1], dp[k + 1][j])
        // 计算在确保胜利情况下的最小成本
        dp[i][j] = Math.min(dp[i][j], cost)
      }
    }
  }
  return dp[1][n]
}
```

```py [py]
class Solution:
    def getMoneyAmount(self, n: int) -> int:
        dp = [[0] * (n + 2) for _ in range(n + 2)]
        for length in range(2, n + 1):
            for i in range(1, n - length + 2):
                j = i + length - 1
                dp[i][j] = float('inf')
                for k in range(i, j + 1):
                    cost = k + max(dp[i][k - 1], dp[k + 1][j])
                    dp[i][j] = min(dp[i][j], cost)
        return dp[1][n]
```

:::

- 时间复杂度：$O(n^3)$，外层循环 `len` 是 `O(n)`，内层循环 `i` 是 `O(n)`，最内层枚举 `k` 也是 `O(n)`，所以是 `O(n^3)`。由于题目给定 `1 <= n <= 200`，`200^3 = 8,000,000`，在计算机的承受范围内。
- 空间复杂度：$O(n^2)$，需要一个二维数组来存储所有区间的状态。

算法思路：

- $dp[i][j]$ 表示在 $[i, j]$ 范围内确保胜利的最小开销
- 枚举猜 $k$，代价为 $k + \max(dp[i][k-1],\ dp[k+1][j])$
- 取所有 $k$ 的最小值

### 3.1. 区间动态规划

**状态定义**：`dp[i][j]` 表示在数字区间 `[i, j]` 内，确保能赢下游戏所需的 **最小现金数**。

**状态转移方程（核心逻辑）**：假设我们在区间 `[i, j]` 内，选择了数字 `k` 作为第一次猜测（`i <= k <= j`）。

1. **如果猜中**：花费为 0（或者说是 `k`，但游戏结束，无需继续支付）。
2. **如果猜错**：我们需要支付 `k` 元。然后根据出题人的反馈，问题被缩小到两个子区间：
      - 如果目标比 `k` 小，问题变成区间 `[i, k-1]`，后续花费为 `dp[i][k-1]`。
      - 如果目标比 `k` 大，问题变成区间 `[k+1, j]`，后续花费为 `dp[k+1][j]`。
3. **最坏情况**：出题人会让你走花费更大的那条路。所以猜 `k` 的最坏花费是：`k + max(dp[i][k-1], dp[k+1][j])`。
    - 如果路 1 的开销更大都能走完，那么路 2 一定也能走完，为了确保任意路径都能胜利，因此选成本大的走。
4. **最优策略**：作为玩家，你要在 `[i, j]` 中所有可能的 `k` 里，选一个让最坏花费最小的 `k`。
     - 上一轮的决策已经确保猜 `k` 后，花费 `cost` 能够保证胜利。
     - 这一轮要做的就是找出所有可猜的 `k` 中，最小的 `cost`，并记录到 `dp[i][j]` 中。

> 重点：理解 3、4

所以状态转移方程为：`dp[i][j] = min( k + max(dp[i][k-1], dp[k+1][j]) )`，其中 `k` 从 `i` 遍历到 `j`。

**边界条件**：当 `i >= j` 时，`dp[i][j] = 0`（区间内只有一个数字或没有数字，不需要猜测或一猜就中，不花钱）。

**遍历顺序**：由于 `dp[i][j]` 依赖于比它更小的区间，我们需要 **按区间长度 `len` 从小到大** 进行遍历。

1. 枚举区间长度 `len` 从 2 到 `n`。
2. 枚举区间起点 `i`，计算出终点 `j = i + len - 1`。
3. 枚举分割点 `k`，计算并更新 `dp[i][j]`。

**猜字顺序**：和遍历顺序相反，**区间从大到小**。

### 3.2. dp 初始化为 `n + 2` 的原因

开辟 n+2 的空间，是为了防止 k+1 越界（当 k=j 时，k+1 = j+1）。
