## 1. 题目描述

- [leetcode](https://leetcode.cn/problems/minimum-size-subarray-sum)

给定一个含有 `n` 个正整数的数组和一个正整数 `target`。

找出该数组中满足其总和大于等于 `target` 的长度最小的子数组 `[numsl, numsl+1, ..., numsr-1, numsr]`，并返回其长度。如果不存在符合条件的子数组，返回 `0`。

---

示例 1：

```
输入：target = 7, nums = [2, 3, 1, 2, 4, 3]
输出：2
```

解释：子数组 [4, 3] 是该条件下的长度最小的子数组。

---

示例 2：

```
输入：target = 4, nums = [1, 4, 4]
输出：1
```

---

示例 3：

```
输入：target = 11, nums = [1, 1, 1, 1, 1, 1, 1, 1]
输出：0
```

---

提示：

- `1 <= target <= 10^9`
- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^4`

---

进阶：

- 如果你已经实现 `O(n)` 时间复杂度的解法，请尝试设计一个 `O(n log(n))` 时间复杂度的解法。

## 2. s.1 - 滑动窗口

<<< ./solutions/1/1.py [py]

- 时间复杂度：$O(N)$，其中 $N$ 是数组长度，左右指针各最多移动一次
- 空间复杂度：$O(1)$，只用常数额外变量

算法思路：

- 数组元素均为正整数，窗口和随右端扩张单调不减、随左端收缩单调不增
- 可用双指针维护最小合法窗口：
  - 外循环：右指针 `right` 向右扩展，累加 `sum`
  - 内循环：当 `sum >= target` 时，用当前窗口长度更新答案，同时再右移左指针 `left` 收缩窗口，尝试找到更小的窗口，直到 `sum < target`
- 全程扫完后若从未满足条件则返回 `0`

## 3. s.2 - 前缀和 + 二分

::: code-group

<<< ./solutions/2/1.js [js]

<<< ./solutions/2/1.py [py]

:::

- 时间复杂度：$O(N\log N)$，建前缀和 $O(N)$，对每个左端点二分 $O(\log N)$
- 空间复杂度：$O(N)$，前缀和数组

算法思路：

- 元素为正 ⇒ 前缀和严格递增，可二分查找右边界
- 令 `prefix[0] = 0`，`prefix[k]` 为前 $k$ 个数之和（`nums[0..k-1]`）
- 枚举起点下标 `i`（子数组从 `nums[i]` 开始），二分最小的前缀下标 `j`（$i < j \le n$），使 $prefix[j] - prefix[i] \ge target$ 即子数组 `nums[i..j-1]` 的和达标；长度是 $j - i$
- 找不到这样的 `j` 则该起点无解

## 4. 【AI】如何理解“进阶”要求的用意？

这句进阶的用意，其实有点「反直觉」：**不是要你做出比 $O(n)$ 更快的解，而是让你再写一种 $O(n\log n)$ 的解法**（见 s.2）。

### 4.1. 为什么看起来像倒退？

本题最优就是 **滑动窗口 $O(n)$**。

$O(n\log n)$ 是 **更慢** 的另一种正确做法（前缀和 + 二分），复杂度：$O(n)$ 建前缀和 + $n$ 次二分 → $O(n\log n)$。

### 4.2. 官方为什么要你写更慢的？

1. **练另一种模板**：前缀和 + 二分，在很多题里会单独考；本题元素为正，刚好能用。
2. **对照两种思路**：有人先想到前缀和二分，再优化成滑动窗口；进阶等于让你把「另一条路」也走一遍。
3. **不是性能要求**：不是说 $O(n\log n)$ 更好，而是「如果你已经会 $O(n)$，再试试这套写法」。

所以：**进阶 = 补充解法练习，不是更优解。** 刷题优先 s.1；s.2 用来巩固「前缀和 + 二分」。
